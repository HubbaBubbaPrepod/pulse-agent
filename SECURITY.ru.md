# Политика безопасности

> [English version](SECURITY.md)

## Сообщение об уязвимости

Используйте [GitHub Private Vulnerability Reporting](https://github.com/HubbaBubbaPrepod/pulse-agent/security/advisories/new). Не публикуйте эксплойты, токены, закрытые ключи, приватные адреса узлов или неочищенные журналы в публичных issues. Укажите версии агента и панели, ОС/архитектуру, минимальный сценарий воспроизведения, последствия и возможные меры защиты. Проверяйте только собственные системы или системы, которыми разрешено управлять. Опубликованного SLA по срокам ответа или сопровождению нет.

## Версии и модель доверия

Первая совместимая публичная пара — Pulse Agent v0.4.0 / Pulse Monitor v0.4.0. Используйте актуальные применимые исправления и читайте [историю изменений](CHANGELOG.ru.md) перед обновлением; совместимость до v1.0 не гарантируется. Политика не обещает перенос исправлений безопасности в старые выпуски.

- Скачивайте официальные релизные архивы и проверяйте `checksums.txt`. Контрольные суммы выявляют повреждение или несовпадение; это не независимая подпись издателя.
- Удалённое подключение к панели требует HTTPS с проверкой сертификата. Loopback HTTP разрешён для разработки. Ограничьте доступ к панели; внутренние CA добавляйте в доверие ОС.
- Каждому узлу нужны собственные токен и каталог состояния. Защитите их права доступа; при компрометации отзовите токен в панели, замените файл и перезапустите агент.
- Нативные модули выполняют код без песочницы с правами агента. Проверка SHA-256 подтверждает скачанные байты; `permissions` модулей не обеспечивают изоляцию ОС. Устанавливайте только доверенные пакеты.
- Доступ к Docker socket — привилегированный доступ к узлу, даже когда модуль делает запросы чтения. TShark/Npcap требуют отдельной установки и прав захвата.
- Командные строки процессов, журналы, адреса соединений и сводки протоколов пакетов могут раскрывать чувствительные данные. Проверяйте доступ к панели и очищайте отчёты перед публикацией.

При компрометации узла или модуля остановите затронутый агент/модуль, ограничьте доступ, сохраните соответствующие журналы и состояние для расследования и смените затронутые credentials. Не удаляйте историю или состояние повторной отправки автоматически при реагировании.

## Изолированные компоненты

WASI-компоненты выполняются во встроенном интерпретаторе без смонтированных файлов хоста, унаследованных секретов, прямого сетевого доступа и запуска нативных процессов. Явные разрешения посредника допускают ограниченные операции Docker или настроенные оповещения. Runtime хоста, посредник и Docker daemon остаются доверенными; 128 MiB ограничивают линейную память гостя, а не весь RSS хоста. Нативные компоненты сохраняют полное доверие. См. [контракт WASI](https://github.com/HubbaBubbaPrepod/pulse-monitor/blob/main/docs/MODULES-WASI.md).
