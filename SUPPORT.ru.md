# Поддержка

> [English version](SUPPORT.md)

Начните с [установки и диагностики](README.md#обновление-удаление-и-диагностика). Выполните `./pulse-agent -check` (`./pulse-agent.exe -check` на Windows): команда собирает локальную сводку без токена и подключения к панели. Проверьте вывод перед публикацией: сведения об оборудовании могут идентифицировать узел.

Проблемы сбора метрик, службы и отправки сообщайте в [Pulse Agent Issues](https://github.com/HubbaBubbaPrepod/pulse-agent/issues). Проблемы панели, учётных записей и истории — в [Pulse Monitor Issues](https://github.com/HubbaBubbaPrepod/pulse-monitor/issues); Docker-модуля — в [Pulse Module Docker Issues](https://github.com/HubbaBubbaPrepod/pulse-module-docker/issues).

Укажите версии, ОС/архитектуру, способ установки, точные шаги воспроизведения, ожидаемое/фактическое поведение и очищенный вывод диагностики. Проверьте ID узла, права файла токена, доверие TLS, исходящий доступ и состояние службы. HTTP 401 означает неверный/отозванный токен. Ограниченные права ОС, отсутствующие драйверы и неподдерживаемое оборудование могут объяснять недоступные показатели; захват пакетов необязателен.

Не публикуйте токены, закрытые ключи, приватные адреса, данные учётных записей и неочищенные скриншоты/журналы. При расследовании сохраняйте локальное состояние и соответствующие журналы: удаление состояния может потерять ожидающий отчёт или курсор журнала. Об уязвимостях сообщайте [приватно](SECURITY.ru.md). Поддержка ведётся через issues репозитория без опубликованного SLA по срокам ответа.
